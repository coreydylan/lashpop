# Vagaro booking integration contract

Read this before changing service booking. This integration was debugged more
than once because several plausible Vagaro URLs do not behave the way their
query parameters imply.

## The only supported service-scoped path

Each bookable service needs the complete URL generated by Vagaro's widget
builder's authenticated `save-widgetdetails` response:

```text
https://www.vagaro.com//resources/WidgetEmbeddedLoader/<opaque-code>?v=<opaque-token>#
```

`BookingView` must inject that URL as a `<script>` inside a `.vagaro` element.
The script creates and initializes the iframe. Preserve the original `?v=`
token and this DOM order:

1. append the loader `<script>` to `.vagaro`
2. append `.vagaro` to the booking container
3. allow Vagaro's loader handshake to create its iframe

Do not set the loader URL directly as an iframe `src`.

The loader path is entirely opaque. Vagaro changed its generated path format
between the original 2025 setup and July 2026, including the portion that had
previously looked like a stable business prefix. No substring of one loader is
safe to reuse when constructing another.

## Known-bad shortcuts

Never substitute either of these for a generated loader URL:

- `Users/BusinessWidget.aspx?...&ServiceID=<numeric id>`
- `/lashpop32/book-now?ServiceId=<numeric id>`

Live browser testing on July 29, 2026 confirmed that the numeric service
parameter does not scope either page. Both can render the full service menu,
usually beginning with Classic lashes. Opening either path from the Service
Browser also breaks the required inline modal behavior.

If a service lacks a verified generated loader URL, fail closed with the
configuration message. Do not rebuild a URL from `vagaro_service_code` and do
not silently fall back to the all-services widget.

## Adding or repairing a service

1. Sign into Vagaro in Safari and open:
   `Settings → Booking → Booking Widget`.
2. From the repository, run:

   ```bash
   npm run vagaro:widgets:audit
   ```

   The audit is read-only. It matches each active database service to Vagaro's
   current widget catalog by **exact service name and parent category**, then
   compares production D1 to the checked-in verified manifest.
3. To generate current loaders for the complete catalog, run:

   ```bash
   npm run vagaro:widgets:refresh
   ```

   This is intentionally a full-catalog operation. It generates and validates
   every loader before making one production D1 update, writes
   `workers/vagaro-sync/src/vagaro-widget-manifest.json`, and restores the
   widget builder state it found at startup. Authentication remains inside the
   open Safari page and is never written to disk.
4. Open the affected services through LashPop's Service Browser and verify:
   - it stays inside the existing modal;
   - there is no "Click to Book" interstitial;
   - the first screen is scoped to the selected service;
   - back/close navigation still works.
5. Run `npm run test:vagaro`, `npm run types`, and `npm run build`.

A numeric `vagaro_service_id` proves only that the catalog row exists. A
five-character `vagaro_service_code` also does not prove that the required
version token is correct. Neither field proves that a widget is correctly
mapped. Do not write an audit that declares mappings valid from numeric IDs,
non-empty URLs, or service codes alone.

## Current Vagaro model (verified July 29, 2026)

The authenticated builder currently uses:

- `GET .../settings/book/serviceandclasses?ServiceProviderId=0` for the
  encrypted service and parent-category catalog;
- `GET .../settings/book/widgetdetails?serviceProviderId=...` for the current
  builder configuration; and
- `POST .../settings/book/save-widgetdetails` to save one exact
  service/category selection and return its generated embed code.

The saved builder configuration is not itself a reusable "base URL." The POST
response creates an opaque loader snapshot for that selection. The safe
automation therefore reuses the builder configuration fields, changes only the
encrypted child/parent selection, and records the complete returned script
`src`.

Parent category is essential. Vagaro currently contains identical titles in
different categories, including Brow Shaping, Microblading, and Nanobrows.
The old CSV importer updated rows by title alone and assigned the same loader
to some of those distinct records. The manifest and refresh tool require the
name/category pair to be one-to-one and require every generated full URL to be
unique.

The following old mechanisms were removed because they can silently corrupt
mappings:

- the hand-maintained five-character service-code JSON;
- CSV parsers that paired names and embed codes by position;
- name-only bulk update scripts; and
- direct arbitrary widget-URL update helpers.
